Preprocessing
=============

Add raw recordings, then prepare five-second samples
---------------------------------------------------
    Keep each complete recording folder directly in Dataset/Data/, including
    audio_000000.wav and metadata.json, plus events/playback when supplied.
    Preserve SourceRecording.Folder for clips from the same original recording.
    Supported WAV input is 44100 Hz, stereo PCM16, one WAV per recording folder.

    Run from the project root using the existing dataset_splits.csv source table:

    python Dataset/Preprocessing/prepare_dataset.py

    By default this prints only the resulting samples.csv path. Use that one
    combined CSV in the existing training command; its split column selects
    train/validation/test:

    python main.py --mode train --task classification --model lstm --csv Dataset/Processed_5s/samples.csv --epochs 20

    The CSV parent is the data/WAV root unless --data-dir is explicitly supplied.
    The checkpoint records the CSV path for resume and later test verification.

    prepare_dataset.py scans new raw recordings, preserves existing assignments
    from dataset_splits.csv, creates full five-second base samples and the selected
    synthetic four classes, and writes the sample CSVs. A completely new source
    defaults to train. New clips from an existing source inherit that source's
    active split. Tails stay separate; generated folders are not new raw inputs.
    Add --verbose for detailed build output.

    Data/ contains the original recording folders and their supplied annotations.
    Generated data always goes to the separate Dataset/Processed_5s/ directory.
    Each run builds and validates temporary output, then replaces Processed_5s/
    and updates current_dataset.json. The published layout contains
    <split>/<label>/<recording_id>/<segment>.wav, samples.csv, companion split
    CSVs, labels, recipe/source snapshots and separately retained short tails.
    segments.csv/json refer directly to unchanged good WAVs as the base samples;
    no duplicate base-WAV set is stored. base_dataset_summary.json retains base
    counts. tails/ and tails.csv/json retain short tails with their true lengths.

    --dry-run previews discovery/counts without writing. --verbose shows progress.
    Original WAVs and model weights are not overwritten. Failed builds leave the
    published dataset intact. Successful builds replace the previous generated
    output; retain a copy elsewhere when needed for an older experiment.
    Full resume and test verification check the saved data identity and reject
    changed inputs. Start a new training run for a changed generated dataset.

    This mode labels original signals good by the current synthetic-demo convention.
    It does not convert manual event quality scores into these four classes.
    Existing CSV target overrides within the four labels are retained only for
    unchanged base PCM. Different class definitions or changed manually labelled
    inputs require review instead of silently losing target edits.

recording_inventory.py
    Read-only discovery and source-group assignment planning.

active_dataset.py
    Standard-library active-directory resolver and atomic pointer publisher.
    It never fits statistics, cuts WAVs, or starts training.

Train the existing four-class five-second WAV dataset
----------------------------------------------------
    From the project root, run one of these commands manually:

    python main.py --mode train --task classification --model cnn --csv Dataset/Processed_5s/samples.csv --epochs 200
    python main.py --mode train --task classification --model lstm --csv Dataset/Processed_5s/samples.csv --epochs 200

    The input is the WAV listed in each row of Processed_5s/samples.csv.
    The split column selects train/val/test; label and label_index supply the target.
    One complete 5-second WAV = one sample. The selected CSV is reread on each run;
    no long-recording segmentation or spectral-feature conversion occurs here.
    Pass another matching dataset's samples.csv with --csv to use a retained copy.

    Manual class configuration: Processed_5s/labels.json is generated by default as
    {"0":"good","1":"sufficient","2":"bad","3":"very_bad"}.
    Model output count comes from this file, not a hard-coded four-class limit.
    Future datasets may define another set of labels with consecutive IDs from 0.
    Their CSV label/label_index fields must match that mapping; CSV labels are the targets.
    Changing class definitions requires a fresh run; saved weights retain their
    original class mapping. Changing labels.json alone does not relabel WAVs.

fourclass_data.py
    Owns CSV loading, WAV decoding, training-only normalization, and tensor shaping
    for classification. It preserves 220500 frames and both channels at 44100 Hz.
    CNN right-pads 44 zero frames after normalization; loss ignores padding.
    LSTM uses the original 220500 frames. The WAV files are never modified.
    CSV metadata must agree with the generation manifest. Same-source segments and
    all four versions stay in one split. Changing source split membership requires
    rebuilding because sine generation used a training-only reference.
    Checkpoints store the fitted normalization for resume and prediction.

export_csv.py
    Generate CSV indexes independently from WAV segmentation or augmentation:

    python Dataset/Preprocessing/export_csv.py --data-dir Dataset/Processed_5s --output-dir "runs/csv_exports/<new-name>"

    Reads the existing classification dataset and exports train.csv, val.csv,
    test.csv, excluded.csv and samples.csv to the new review directory.
    Existing split-CSV labels override generation-time labels.
    Source groups and WAVs remain unchanged. Relative WAV paths still resolve
    against the original data_dir, not the export directory. The export directory
    is not a standalone --data-dir. Use --output-dir to choose a new empty folder.
    Without that option, exports go to Dataset/CSV_exports/<timestamp>/, outside Data/.

waveform_frames.py
    Groups normalized Tensor samples without discarding values, averaging,
    resampling, or converting to spectra. frame_waveform maps (B,T,C) to
    (B,ceil(T/frame_size),frame_size*C); unframe_waveform reverses this layout
    and removes only internal tail padding. Device, dtype and gradients remain.
    Fresh LSTM classification uses frame_size=441, so a full five-second
    (B,220500,2) input is processed as (B,500,882). The decoder reconstructs
    the original 220500-by-2 waveform. The physical WAV files are unchanged.
    Configure with --lstm-frame-size; checkpoints save the value. Old checkpoints
    without it retain frame_size=1 and cannot be resumed into a different shape.

company_data.py
    Shared company WAV loading, complete-window selection, train/validation/test construction, and training-only channel normalization. Both CNN1D-VAE and LSTM-VAE import this implementation.
    Default signal directory: ../Data/
    Default split CSV: dataset_splits.csv in this directory.

dataset_splits.py
    Reads the current CSV on every data-loading call, validates source-recording separation, and saves the assignments used by a run.

dataset_splits.csv
    Current company sample assignments: 25 train, 3 val, 3 test, and no excluded recordings. The 15 additional clips are now included in training; each original source group remains in one split.

build_segments.py
    Internal segmentation step used by prepare_dataset.py. It builds five-second
    base samples from the original recordings and the current source split CSV.
    Current complete sample counts: train295, val35, test39. Every sample has 220500 frames, 44100 Hz, two channels, and 16-bit PCM.
    Short tails are stored separately with their true duration and are excluded from the fixed-length train/val/test sample tables. Original PCM bytes and source grouping are preserved.
    Base labels are good by the professor's original-signal convention; event states and quality ratings are separate fields. Sine-injected sufficient/bad/very_bad variants are not generated by this builder.
    Existing reconstruction models still use their saved 2048-point input windows. Five-second data export does not change the model architecture or launch classification training.

build_fourclass.py
    Internal synthesis step used by prepare_dataset.py. It builds the artificial
    classes from complete base segments using fourclass_config.json. The normal
    entry publishes the resulting WAVs and CSVs directly in Dataset/Processed_5s/.
    The current 369 base segments yield 1476 actual five-second PCM16 stereo WAV files: 369 unchanged-good versions and 1107 sine-injected variants. Counts are train1180, val140, test156; each label has train295, val35, test39. The 27 original short tails are not synthesized.
    The labels good, sufficient, bad, and very_bad describe original/synthetic amplitude tiers. They are not measured fault states or real machining-quality ground truth. Manual original_quality_score and machine_state are retained separately; numeric quality=3 is not a four-class label.
    Every version inherits its base segment's source_recording_id and split. Never re-split the four variants or same-source segments across train/val/test.
    Outputs include samples.csv, samples.json, train.csv, val.csv, test.csv,
    labels.json, resolved_config.json and dataset_summary.json. Use prepare_dataset.py
    for the complete build-and-replace workflow.
    Amplitude/phase/label_index, base/sample IDs, and filenames are label or provenance metadata, not classifier input features. Learn from the WAV signals and use class labels as targets.
    This step does not retrain any model. The current 2048-point reconstruction and three-class MSM interfaces are not automatically converted to five-second four-class classification.

fourclass_config.json
    Current engineering defaults, not yet exactly confirmed by the professor: add a 1000 Hz sine to the right channel only; peak-amplitude ratios good=0, sufficient=0.5, bad=1.5, very_bad=3.0.
    The only reference is the median original right-channel RMS over the 295 training base segments, currently 290.2423828895374 PCM counts. Validation/test data and tails do not enter this calculation.
    One random phase and one amplitude multiplier within [0.9,1.1] are shared by the four versions of each base segment; only the class ratio changes. Seed: 20261109. The resolved recipe and training-only reference are saved in resolved_config.json.

msm_dataset_splits.csv
    MSM experiment assignments. Initially 23 train, 7 val, and 7 test.

prepare_msm.py
    Aligns MSM Sound0 and Acc0 signals, resamples acceleration, and selects labeled
    windows. Supply --raw and an output directory outside the original Data/ tree.

demo_windows.py
    Reproduces the one-second WAV and manual-label demonstration for the opening-pocket start sample. It preserves the original PCM values and the short final clip. Use --output to write a new demonstration directory; existing clips are not overwritten.

Run these commands from the project root:

    python Dataset/Preprocessing/prepare_dataset.py
    python Dataset/Preprocessing/prepare_msm.py --raw /path/to/MSM/imi_vm20i --output /path/to/msm_prepared
    python Dataset/Preprocessing/demo_windows.py --output /path/to/new_demo

Select a training model through the project-root main.py:

    python main.py --mode train --model cnn --epochs 3
    python main.py --mode train --model lstm --epochs 3
    python main.py --mode train --model both --epochs 3

The default mode is train, so earlier commands such as --model cnn --epochs 3 remain compatible. The default task is reconstruction: company WAV VAE reconstruction, with the same shared company_data.py preprocessing and dataset_splits.csv for either model. Add --split-csv to use another table or --windows-per-recording to change the sampling limit.

After preparing the MSM arrays, select its classification task:

    python main.py --mode train --model cnn --task msm --prepared /path/to/msm_prepared --epochs 30
    python main.py --mode train --model lstm --task msm --prepared /path/to/msm_prepared --epochs 30
    python main.py --mode train --model both --task msm --prepared /path/to/msm_prepared --epochs 30

MSM keeps the three classes normal_cutting, abnormal_cutting, and defective_tool_normal_cutting. Selecting cnn, lstm, or both changes the trained model, not the preprocessing method or label definitions. The original model-directory training commands remain available.

The unified launcher uses the current Python interpreter and resolves relative paths from the project root. Each training invocation writes to runs/train/<timestamp>/<task>/<model>/, where model is cnn or lstm. The timestamp uses Europe/Lisbon time in YYYY-MM-DD_HH-MM-SS_microseconds format. A both-model invocation shares one timestamp; separate invocations receive separate directories. --output-dir changes the base while retaining train/<timestamp>/<task>/<model>. Existing nonempty trainer output directories are rejected.

Start a fresh 200-epoch run and evaluate every 20 epochs:

    python main.py --mode train --model cnn --epochs 200 --eval-every 20
    python main.py --mode train --model lstm --epochs 200 --eval-every 20

--epochs is the total target epoch, not an additional count. --eval-every defaults to 20; the final epoch is also evaluated. Validation and test are evaluated at each point by default. Test scores are observational only: optimization, best-checkpoint selection and early stopping do not use them. Reconstruction selects the lowest evaluated validation reconstruction MSE; MSM selects the highest evaluated validation interval Macro F1.
Use --no-test-during-training to disable periodic test observation when needed; final test evaluation remains enabled. The default observes both validation and test every evaluation point.

The run saves last.pt after every completed epoch, periodic checkpoints/epoch_0020.pt etc., a validation-selected best.pt, and final.pt at completion. Reconstruction keeps smoke_trained.pt as an interface-compatible output; MSM keeps best_classifier.pt. Use last.pt for continuation; it carries the completed training epoch, optimizer and RNG state.

Continue a run toward epoch 300 (replace the placeholder with the real previous directory):

    python main.py --mode train --model cnn --resume "runs/train/<previous-timestamp>/reconstruction/cnn/last.pt" --epochs 300

--resume requires an existing checkpoint and a single matching training model/task. It is rejected for both, predict and stream. Continuation also creates a new timestamped directory, preserving the checkpoint source. Full-state resume restores weights, optimizer, completed epoch and Python/NumPy/CPU-PyTorch/loader-generator RNG state, reusing the saved data, normalization and optimization settings. The total epoch target can be extended, and evaluation settings can be changed explicitly. If interrupted during an epoch, continuation starts after the last completed saved epoch.

Historical files remain where they are, including the 200-epoch runs/reconstruction/cnn/smoke_trained.pt and each model's artifacts directory. Legacy checkpoints without optimizer/RNG state support explicitly reported weights-only continuation with optimizer reset; they cannot exactly restore the earlier training process. Training resume is separate from gRPC or streaming-connection recovery.

Training timestamps do not change offline prediction or streaming output paths.

Prediction loads a saved checkpoint and its normalization without retraining. Choose one model (cnn or lstm), and supply both --checkpoint and --wav:

    python main.py --mode predict --model cnn --checkpoint runs/reconstruction/cnn/smoke_trained.pt --wav Dataset/Data/20261012_124615/audio_000000.wav
    python main.py --mode predict --model lstm --checkpoint LSTM-VAE/artifacts/smoke_trained.pt --wav Dataset/Data/20261012_124615/audio_000000.wav

The CNN example uses the saved 200-epoch reconstruction model; the LSTM example uses its retained short-training checkpoint. Prediction does not read the split CSV or refit the saved normalization. --max-windows defaults to 0 (all complete windows); use a positive number to limit the initial windows. A partial final window is reported separately.

The default prediction JSON path is runs/prediction/<model>/<wav-parent-folder>/<wav-stem>_<checkpoint-stem>.json. --output selects an exact JSON file; --output-dir changes the default output base. The JSON includes the absolute checkpoint_file and per-window reconstruction errors and latent features, not state-class labels.

WAV prediction supports task reconstruction and task classification, each with a matching checkpoint and a single model. Classification accepts one complete five-second WAV and returns the checkpoint's configured class scores. MSM state classification requires aligned Sound0 PCM and independently measured Acc0 acceleration at 48 kHz through its StateEngine interface.

Stream a saved WAV at its recorded timing through the same main.py entry point:

    python main.py --mode stream --model cnn --checkpoint runs/reconstruction/cnn/smoke_trained.pt --wav Dataset/Data/20261012_124615/audio_000000.wav
    python main.py --mode stream --model lstm --checkpoint LSTM-VAE/artifacts/smoke_trained.pt --wav Dataset/Data/20261012_124615/audio_000000.wav

These examples use reconstruction checkpoints; replace historical paths with existing checkpoints from your runs. Streaming supports one model and task reconstruction or classification with matching weights; both remains training-only. main.py streaming defaults to real-time pacing; --no-realtime requests fast replay. It reads the entire WAV and does not accept --max-windows.

For the new five-second classification model:

    python main.py --mode stream --task classification --model cnn --checkpoint /path/to/classification/best.pt --wav /path/to/input.wav

Classification accumulates 220500 valid frames per result and uses the same saved
normalization and label mapping as offline prediction. Short tails are reported,
and sessions are reset between recordings. Validation/verify_classification.py
checks the held-out test CSV and file/stream agreement after training completes.

Input blocks default to --chunk-ms 20, or 882 frames at 44.1 kHz. The model is loaded once and buffers two-channel PCM until a complete 2048-frame window is available. Each result is immediately written and flushed to JSONL. The current LSTM resets its hidden state for each window. The saved normalization is reused, without reading the split CSV or refitting it.

The console shows the first result and then approximately one latest-window update per second, including overall/L/R standardized reconstruction MSE. The final summary includes mean errors and processed signal duration. The JSON report also retains real replay timing and residual frames. Reconstruction errors are not state-class labels or calibrated fault probabilities.

Default streaming output:

    runs/stream/<model>/<wav-parent-folder>/<wav-stem>_<checkpoint-stem>.jsonl
    runs/stream/<model>/<wav-parent-folder>/<wav-stem>_<checkpoint-stem>_report.json

--output selects the exact JSONL file. --report selects the summary file; otherwise it is saved beside the output as <output-stem>_report.json. --output-dir changes the base while retaining the stream/model/recording structure.

Use --reference-json to compare with complete offline predictions produced from the same WAV and checkpoint. For the CNN example, the matching main.py prediction result is runs/prediction/cnn/20261012_124615/audio_000000_smoke_trained.json. A limited-prefix prediction is not a full streaming reference.

This is WAV-paced replay; live microphone capture and gRPC transport require separate input integration. Direct model-specific stream_wav.py calls remain supported and require --realtime for paced replay, whereas main.py --mode stream already enables it. For example:

    python CNN1D-VAE/stream_wav.py --checkpoint runs/reconstruction/cnn/smoke_trained.pt --wav Dataset/Data/20261012_124615/audio_000000.wav --realtime --output runs/cnn_stream.jsonl --report runs/cnn_stream_report.json

Running main.py without arguments only shows help. In PyCharm, use main.py with the project-root working directory. Choose --mode train for training, --mode predict for offline prediction, or --mode stream for paced WAV replay, together with the matching model/checkpoint arguments above.

Changing a split CSV affects the next fresh training run. The running experiment keeps the assignments it has already loaded, and a full checkpoint continuation preserves its saved data configuration and normalization. Each run saves dataset_splits_used.csv. The CSV selects data membership; it does not create missing event or quality labels. To continue an earlier 16-recording checkpoint, select its saved dataset_splits_used.csv with --split-csv. When rebuilding a segmented dataset after assignment changes, choose a new --output directory; generated manifests and folders are a build-time snapshot.
